Multica 默认使用邮箱验证码登录，也可以增加 Google OAuth。已经存在的用户始终可以再次登录；注册限制只决定是否允许创建新账号。

## 邮箱验证码

用户输入邮箱后，Multica 会发送一个 6 位验证码。验证码 10 分钟内有效，验证成功后浏览器获得登录 cookie。

邮件可以通过 Resend 或 SMTP 发送。两者同时配置时，`SMTP_HOST` 优先。

### 使用 Resend

1. 在 [Resend](https://resend.com/) 验证发信域名并创建 API key。
2. 设置：

 ```dotenv
 RESEND_API_KEY=re_xxxxxxxxxxxxxxxx
 RESEND_FROM_EMAIL=noreply@example.com
 ```

3. 重启 API 服务。

`RESEND_FROM_EMAIL` 必须属于已经在 Resend 验证的域名。

### 使用 SMTP

最少需要设置主机和发件地址：

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USERNAME=multica
SMTP_PASSWORD=<password>
SMTP_FROM_EMAIL=noreply@example.com
```

常见连接方式：

| 场景 | 配置 |
|---|---|
| 内网匿名 relay | `SMTP_PORT=25`，用户名和密码留空 |
| STARTTLS | `SMTP_PORT=587`，默认会在服务器支持时升级 TLS |
| 隐式 TLS | `SMTP_PORT=465`，或显式设置 `SMTP_TLS=implicit` |

如果没有设置 `SMTP_FROM_EMAIL`，会回退到 `RESEND_FROM_EMAIL`。私有 CA 或自签证书需要把 CA 加入容器信任库；`SMTP_TLS_INSECURE=true` 会跳过证书校验，只应在可信内网中临时使用。

有些严格的 relay 还要求合法的 EHLO 名称：

```dotenv
SMTP_EHLO_NAME=mail.example.com
```

### 无邮件服务时的行为

服务器仍可启动，但验证码和邀请链接只会写入日志，不会发送邮件。这适合本地开发，不适合生产环境。

启动日志会说明当前使用的是 `Resend API`、`SMTP relay` 还是 `DEV mode`。

## 本地固定验证码

本地自动化测试可以设置固定验证码：

```dotenv
APP_ENV=development
MULTICA_DEV_VERIFICATION_CODE=888888
```

验证码必须是 6 位数字。`APP_ENV=production` 时固定验证码会被忽略。

<Callout type="warning">
不要在公网实例中启用固定验证码。生产环境的组合是 `APP_ENV=production` 加空的 `MULTICA_DEV_VERIFICATION_CODE`。
</Callout>

## Google 登录

1. 在 [Google Cloud Console](https://console.cloud.google.com/) 创建 OAuth 2.0 client。
2. 把 Multica 前端的回调地址加入 **Authorized redirect URIs**：

 ```text
 https://multica.example.com/auth/callback
 ```

3. 设置：

 ```dotenv
 GOOGLE_CLIENT_ID=xxxxx.apps.googleusercontent.com
 GOOGLE_CLIENT_SECRET=GOCSPX-xxxxxxxxxxxxxxx
 GOOGLE_REDIRECT_URI=https://multica.example.com/auth/callback
 ```

4. 重启 API 服务。

Google Console 与 `GOOGLE_REDIRECT_URI` 中的地址必须完全一致，包括协议、端口和结尾斜杠。配置生效后，登录页会出现 Google 登录按钮；前端镜像不需要重新构建。

## 单点登录（OIDC）

Multica 使用标准 OpenID Connect，因此任何发布 discovery 文档的身份提供商都可以接入：Keycloak、Authentik、Okta、Auth0、Entra ID。下面以 Keycloak 为例，其他提供商的变量完全相同。

### 1. 在身份提供商处注册客户端

在 Keycloak 中打开你的 realm 并创建客户端：

- **Client type**：`OpenID Connect`
- **Client authentication**：`On` —— Multica 是机密客户端，始终发送 client secret
- **Valid redirect URIs**：填写下面这个地址，必须完全一致

```text
https://multica.example.com/auth/oidc/callback
```

<Callout type="warning">
身份提供商会逐字节比对，因此协议、端口和结尾斜杠都必须一致。请使用你的 Multica 站点地址，也就是平时登录的那个域名。如果 API 部署在独立主机上，则改用 **API** 的地址——`/auth/oidc/callback` 由它提供。
</Callout>

在客户端的 **Credentials** 标签页复制生成的 client secret。

### 2. 配置 Multica

```dotenv
OIDC_ISSUER=https://sso.example.com/realms/multica
OIDC_CLIENT_ID=multica
OIDC_CLIENT_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
OIDC_PROVIDER_NAME=Keycloak
```

`OIDC_ISSUER` 是提供 `/.well-known/openid-configuration` 的基础 URL —— Keycloak 为 `<base>/realms/<realm>`。重启前先确认：

```bash
curl -s https://sso.example.com/realms/multica/.well-known/openid-configuration | head
```

回调地址会自动推导：优先使用 `MULTICA_PUBLIC_URL`，未设置时使用 `MULTICA_APP_URL`（或 `FRONTEND_ORIGIN`）。只有当两者都无法描述身份提供商应跳转的地址时，才需要显式设置 `OIDC_REDIRECT_URI`。

### 3. 重建 API 容器

```bash
docker compose -f docker-compose.selfhost.yml up -d backend
```

请用 `up -d` 而不是 `restart`：Compose 在**创建**容器时固定环境变量，`restart` 会沿用旧值，新的 `OIDC_*` 配置不会生效。

登录页随即显示 **使用 Keycloak 登录** 按钮。所有配置都在运行时从 `/api/config` 读取，无需重新构建前端镜像。桌面应用会显示同样的按钮，并打开浏览器完成登录。

### 账号如何匹配

Multica 通过 `email` claim 识别用户：已有 Multica 账号的邮箱会登录到该账号，其他邮箱则在下文[注册范围控制](#注册范围控制)的约束下创建新账号。上线前有两点需要了解：

- **身份提供商必须返回邮箱。** 请授予 `email` scope，并确认该 claim 已映射进 ID token 或 userinfo 响应。
- **当身份提供商报告邮箱未验证（`email_verified: false`）时，登录会被拒绝。** 否则，任何能在你的 IdP 自助注册的人都可以通过邮箱匹配占用同事的账号。完全不返回该 claim 的提供商则会被接受。

如果你的身份提供商会联合外部身份，请将 `ALLOWED_EMAIL_DOMAINS` 设为公司域名。

### Scope

默认请求 `openid email profile`。可通过 `OIDC_SCOPES` 追加（以逗号或空格分隔）；省略 `openid` 时会自动补上。

### 排查

| 现象 | 含义 |
|---|---|
| 没有 SSO 按钮 | `OIDC_ISSUER` / `OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` 中有一项未设置。API 启动日志会指出是哪一项 |
| 提示"此实例未配置 SSO" | `MULTICA_APP_URL`、`MULTICA_PUBLIC_URL` 和 `OIDC_REDIRECT_URI` 均为空，无法推导出回调地址 |
| 提示"身份提供商拒绝了此次请求" | client id、client secret 或回调地址与身份提供商处注册的不一致 |
| 提示"本次登录已过期或已被使用" | 登录耗时超过 15 分钟，或浏览器丢弃了事务 cookie。请检查 `COOKIE_DOMAIN` 是否覆盖 API 主机 |
| 提示"未提供邮箱地址" | 客户端缺少 `email` scope 或邮箱 claim mapper |

## 注册范围控制

三个变量共同决定新账号能否创建：

| 变量 | 作用 |
|---|---|
| `ALLOWED_EMAILS` | 允许的完整邮箱，多个值用逗号分隔 |
| `ALLOWED_EMAIL_DOMAINS` | 允许的邮箱域名，多个值用逗号分隔 |
| `ALLOW_SIGNUP` | 未配置任何白名单时，是否允许注册；默认 `true` |

判断顺序如下：

1. 邮箱命中 `ALLOWED_EMAILS`，允许；
2. 或域名命中 `ALLOWED_EMAIL_DOMAINS`，允许；
3. 未命中时，如果 `ALLOW_SIGNUP=false`，拒绝；
4. `ALLOW_SIGNUP=true` 但设置了任意白名单且未命中，仍然拒绝；
5. 没有设置白名单且 `ALLOW_SIGNUP=true`，允许。

常见配置：

```dotenv
# 只允许公司域名
ALLOW_SIGNUP=false
ALLOWED_EMAIL_DOMAINS=company.com

# 再放行一位外部协作者
ALLOWED_EMAILS=partner@example.net
```

<Callout type="info">
两个白名单在 `ALLOW_SIGNUP=false` 时也可以作为明确的例外名单。
</Callout>

## 邀请与注册限制

邀请不会自动绕过注册限制：

- 对方已经有 Multica 账号时，可以登录并接受邀请；
- 对方还没有账号时，邮箱必须符合上面的注册规则。

在关闭开放注册的实例中邀请新成员时，先把对方邮箱加入 `ALLOWED_EMAILS`。账号创建并接受邀请后，可以再从名单中移除。

## 登录有效期

会话会滑动续期。下面这个值是**闲置**上限，不是从登录开始倒计时：会话剩余有效期低于一半时，下一个请求就会把它续到完整有效期，所以持续使用的账号不会被定时踢出。没有绝对上限。

这个上限是单边的。只有掉到一半以下才会续期，因此最后一次使用时仍有超过一半有效期的会话不会被延长 —— 能保证活下来的闲置时长是下面这个值的一半，而不是全部。

可以用 `AUTH_TOKEN_TTL` 调整，支持 Go duration 或正整数秒数：

```dotenv
AUTH_TOKEN_TTL=720h
```

最小值是 `60s`，更小的取值会被上调到 `60s` 并在启动时打出警告。低于这个值时，服务端算出的续期检查间隔会低于客户端对它设置的下限，客户端的检查频率就会低于会话能存活的时长。

修改后需要重启 API 服务。这个值对之后签发或续期的会话生效 —— 因为会话会滑动续期，已有会话会在下次续期时用上新的有效期。
